SmartConfig

A safety net for the config files that take a Linux machine down. Snapshot a file before it changes, warn before a bad edit lands, explain what broke, and put one file back from the rescue shell.

    What exists today · M1

    One static binary, three layers, two places on disk

    cmd/sc

    the CLI, built on cobra
    initsnapshotlogcatdiffrestore

    Thin. Any error becomes one line, sc: … on stderr, and exit code 1.

    calls

    internal/store

    history of every file
    InitOpenSnapshotListGetBlobRestoreUnifiedDiff

    Content-addressed blobs plus one SQLite row per change. Resolves id prefixes and verifies each blob's checksum before use.

    reads and writes files through

    internal/fsutil

    the only code that touches files
    ReadWithMetaWriteAtomic

    Refuses symlinks, non-regular files and anything over 8 MB. Writes a temp file, sets owner and mode, fsyncs, then renames it over the original.

    on disk

    /etc/…

    The live config files. Only ever replaced by rename, never truncated in place.

    How an id is made
    sha256(path + "\n" + ts + "\n" + blob)[:6]

    Two rows for the same file, content and second would get the same id. When an id is taken, \n1, \n2… is appended and it is hashed again. This happened in the real acceptance run: d2b20b and 0beb81 hold the same bytes, saved in the same second.

    Next · M2

    The watcher: snapshots you never have to remember

    Today a snapshot happens only when someone runs sc snapshot. M2 adds scd, a daemon that watches config files with inotify and records every save, whether it comes from vim, nano, sed or apt. It writes into the same store, so sc log, diff and restore work on its snapshots unchanged.
