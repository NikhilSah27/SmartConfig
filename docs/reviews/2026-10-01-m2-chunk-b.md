# Review of M2 chunk B (steps 6-10)

Date: 2026-09-30 to 10-01. Normal review, as the plan asks for chunk B: two
reviewers (AI agents, each in its own clone, running the code and trying to
break it), one on the store (record, restore), one on the file system, the
CLI and M1 compatibility. Claude then acted as the skeptic and reproduced
each finding before fixing it. Nothing touched the repo, `/etc` (read only)
or the real store.

**Held up:** across about 350,000 reads racing a swap between a file, a
FIFO and a symlink to a secret, `ReadState` never followed the last
component and never blocked; a watcher process racing a file, link or
deletion restore never wrote a row after the restore row; `make m1-compat`
passes and leaves the checkout untouched.

## Not defects

- Paths a restore writes through are checked by `safeDir` and the last
  directory by `O_NOFOLLOW`, but higher directories are followed by path.
  No exploit was found (a swap makes the rename fail); a dirfd-based restore
  is M4, as the plan says.
- Restoring the store's own `changes.db` is refused only because its stamp
  keeps changing. Harmless.
- `ReadState("f/")` reads `f`; not reachable from the CLI (paths are
  absolute and clean).
- A hard link to a fingerprint-only file under another name is not
  recognised; making one needs root. Noted for M3.
