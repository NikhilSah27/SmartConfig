# Final gate review before the m1 tag (round 3 fixes and M1 spec)

Date: 2026-09-28. Three reviewers (restore/snapshot logic, signals and lifecycle, M1 spec conformance), two skeptics per finding. 18 findings, all confirmed; the skeptics rated every one low except one missing test (medium/low). No data loss was found.

Raw results: `~/smartconfig-work/review-r3-results.json` on the VM.

## Round 4 (before the m1 tag)

| Id | Change | Findings it closes |
|---|---|---|
| R4-1 | sc: rework signal handling. The first SIGINT/SIGTERM/SIGHUP/SIGQUIT asks the store to stop at the next safe point (no new work, no more COMMIT retries, never between a rename and its report); `sc` then exits 1 through its normal error path, so defers remove temp files and the message tells the truth ("interrupted (file not changed)" or "file restored but not recorded; previous content saved as ID"). A second signal forces the old sweep-and-exit. Signals inherited as ignored stay ignored. SIGQUIT no longer dumps a stack trace. | logic 1, lifecycle 1-6 |
| R4-2 | tests for spec clauses that had none: setuid/setgid/sticky restore and the printed mode, the existed/did-not-exist guards and the retry limit in Restore, the id formula, `-q` when unchanged, "no previous file existed", log column order and local time | logic 2, spec 1, spec 4 |
| R4-3 | fsutil: "replaced while being read" is a retryable error; Snapshot and Restore retry it like a stamp change | logic 4 |
| R4-4 | MILESTONES.md: list every deliberate deviation and known limit that the m1 tag certifies (restore needs a readable current file under 8 MB; retries can add pre-restore rows; stamp granularity on coarse filesystems; logrotate and temp names; ...) | spec 2, spec 3, logic 3, 5, 6 |

## Deferred (recorded as known limits)

- `sc log` prints intents and paths raw; a newline or tab in an intent breaks the table (spec 5). Later: escape control characters.
- Some errors lack operation context; `sc help <unknown>` exits 0 with usage text (spec 6). Later.
- The stamp can miss a same-size in-place rewrite within the timestamp granularity on filesystems with coarse timestamps (vfat, ext4 with 128-byte inodes); not on this VM (logic 5).
