## Held up

- No path in the script writes a real file in its normal flow. The made-up fstab and
  the grub.d with `42_smartconfig` exist only in private mount namespaces, grub-mkconfig
  writes only its `-o` file, and `BindPaths=` fails closed.
- grub-editenv rewrites grubenv in place, so the bound copy takes the write. Set and then
  unset, the copy is the real block byte for byte.
- The restore refusal strings, the hot-journal recipe (a real hot journal: magic
  `d9d505f9`, nRec 1), `reads()`, and every section 3 and 7 check pass when replayed as
  a user. Real grub-mkconfig output for this VM is the same on two runs.
- The README's rescue report is line for line the lab's UEFI run of `22383a0`. Every
  number, exit code, path and VM fact in the docs checks out against the code, plan and
  machine. The install and removal commands are sound (`install` replaces the binary
  under a running scd safely).
- A whole-boot `systemd-analyze verify graphical.target` with both units added shows no
  ordering cycle; a control with a deliberate cycle was caught. That was chunk C's open
  item.

## Not verified
