## Adversarial check of the fixes

**Refuted, then fixed.** The console could still pass 25 rows:
- a symlink row's "now a symlink to TARGET" had no length cap;
- a new file's `mv PATH PATH.sc-off` wrapped for any path over 33 characters.

Both now fit:
- a row budget counts screen rows, so a wrapped line counts twice;
- the problem column is cut to 40;
- a symlink's target is left out;
- a new file is moved aside with `cd DIR` and a short `mv`;
- `fit()` cuts at a rune boundary.

**Issues it raised, fixed:**
- The seen unit's comment "nothing waits for it" was now false.
- `RequiresMountsFor=/usr/local/sbin` was added: with a separate `/usr/local`, the condition was checked before the mount.
- powerpc encodes `FS_IOC_GETFLAGS` as `0x40086601`, so there is now a constant per architecture.
- `ReplaceRefused` opened FIFOs and devices; it now opens only regular files and directories.
- It reported one flag per run; it now reports every flag at once.
- A console error reached only `/dev/console`; it now goes into the report.
- "The menu shows once more" was wrong when rescue was entered from a healthy boot.
- `no_entry` was not initialized.

**Found by the step 11 design:**
- `sc status` read the mode only from `emergency.target` and `rescue.target`.
- In the drop-in, only `emergency.service` or `rescue.service` is activating, and the target is reached after it.
- So the fstab-failure emergency report said "normal", with no `daemon-reload` and no reboot.
- It now reads the services too.

**Deferred:**
- A multipath root: `10_linux` switches to `/dev/mapper/<name>` and 42 gives `UUID=`. This sits with the LVM and LUKS non-goals.
- A whole-boot ordering-cycle test with the real grub units: `verify` runs each unit alone.
- The console report is held until `sc` returns, so a hung `sc` shows nothing; the shell still starts.

## Held up

- **The lab's 11 boots, UEFI and BIOS:**
  - The rescue entry booted 4 times, each with a read-only root and `/boot` not mounted.
  - The flag was set at seen, cleared on ok and kept on bad: 6 ok verdicts and 1 bad.
  - Every flagged boot showed a 30 s menu even with `GRUB_TIMEOUT=0` and `GRUB_RECORDFAIL_TIMEOUT=0`.
  - The case recordfail misses was caught: the fstab failure went on to multi-user, recordfail was cleared, and the flag stayed.
- **The drop-in:** the report printed directly above "Press Enter" in emergency and rescue mode, and exit 2 did not stop the shell.
- **`ReplaceRefused`:** it matches the kernel. A `+a` directory blocks a rename into it, a `+a` target blocks a rename over it, and a `+i` directory blocks a create.
