## Not defects, left for a decision

- **Secrets stored with content, as the plan accepts.** `/etc/shadow`,
  `/etc/gshadow`, `grub.cfg`, the netplan and cloud-init network files
  (0600), sudoers and the ufw rules are recorded with content in the
  root-only store. Plan section 12 notes the store holds such copies, and
  section 15 defers redaction in `sc diff` and `sc cat` to M3. Restoring
  `/etc/shadow` is part of undoing a lockout, so fingerprinting it would
  lose rescue value.
- **Secret families not on this VM but stored with content if they
  appear:** dropbear-initramfs host keys, `/etc/wireguard/*.conf`,
  `/etc/apt/auth.conf.d/*`, LUKS key files (`/etc/cryptsetup-keys.d`).
  Raised with you as a scope question.
- **`~/.ssh/rc` and `~/.ssh/environment`**: sshd reads both, block C
  excludes them. Raised with you as a scope question.
- **Several `**` in one pattern** can take 0.9 s on a depth-200 path; only
  the built-in scope exists in M2, and it has no such pattern.
- The real-listing test can only flag excluded paths that a tier 1-2 line
  names, so a D2-style gap in a tier 3-4 directory would pass it. The
  synthetic names are the guard for those.
