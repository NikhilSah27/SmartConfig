# Review of the M1 follow-up fixes (c720f22, ec15ece)

Date: 2026-09-27. Three reviewers (concurrency, security, regressions) ran the code and tried to break it; every finding was re-checked by two skeptics told to refute it. A finding counts as confirmed when both skeptics agree it is real.

**Result:** 14 findings, 13 confirmed and 1 split; none breaks M1 as used today (root runs `sc` by hand, one command at a time). Most matter once the M2 watcher runs next to `sc`, so they are fixed before M2 (round 2, R2-1 to R2-5) or covered by steps in the M2 plan.

Raw results (with full evidence) are kept on the VM in `~/smartconfig-work/m2plan-results.json`.

## Security

Checked and fine: 11 items, for example:

- O_NONBLOCK does not change reads of regular files. Go 1.22 os.OpenFile with O_NONBLOCK uses kindNonBlock (GOROOT/src/os/file_unix.go:297-298, 178-236). Registering a regular file with epoll fails, so Go falls back to plain read(2), which ignores O_NONBLOCK on regular files, and mandatory locking no longer exists on this kernel. The one difference is at open time under a file lease (finding 3).
- FIFO swap: an O_NONBLOCK open of a FIFO with no writer succeeds, and SameFile/CheckRegular (fsutil.go:64-69) reject it before any read. The existing TestReadCheckedRefusesSwap covers this.
- os.SameFile compares dev and inode only (GOROOT/src/os/types_unix.go:28-29). Overlayfs in a scratch mount, lower-layer file: dev=57 ino=1316568 before and after a metadata copy-up (chmod) and a data copy-up (append), and readChecked returned nil each time. ## Regressions

Checked and fine: 16 items, for example:

- Build and static checks: the CGO_ENABLED=0 build gives 'ELF 64-bit LSB executable ... statically linked'. go vet ./... and gofmt -l print nothing.
- Tests as the normal user: go test -count=1 ./... gives ok for cmd/sc, internal/fsutil and internal/store.
- Tests as root: sudo env PATH GOCACHE GOMODCACHE CGO_ENABLED=0 go test -v ./... passes all tests, including TestRestoreOwner (it runs only as root), TestRestoreHoldsLockAcrossRename and TestRestoreWriteFailureRecordsNothing.
- Race detector: cgo and gcc are available, so it could run. CGO_ENABLED=1 go test -race -count=3 ./... and -cpu 1,4,8 on internal/store are clean. No store test uses t.Parallel, and the hook is set, run and cleared on the test goroutine.
