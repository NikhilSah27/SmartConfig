# M2 watch list: what scd watches, ignores, and must beware of

Research for milestone 2 (the `scd` watcher), done on the development VM (Ubuntu 24.04.5, kernel 7.0.0-34, systemd 255, GRUB 2.12) on 2026-09-27. Six research agents surveyed boot, access, network/apt, a census of `/etc`, inotify behaviour (real experiments with sed, nano, install, mv, visudo, dpkg-style renames and `sc restore`), and prior art (etckeeper, AIDE, CIS audit rules). A synthesis merged them; 8 key claims were re-tested by independent verifiers trying to refute them; a completeness critic looked for gaps. Nothing under `/etc` or `/boot` was modified (only `inotify-tools` was installed, which rebuilt `/etc/ld.so.cache`).

**Status:** research only. No M2 code exists. The decisions in section 8 come first.

## 1. Tiers: what to watch

### Tier 1: boot

A mistake stops the machine booting or reaching a usable state. Watch by default and alert loudly. Many of these only take effect after a regeneration command, which unattended upgrades run with no human present.

| Path | Why it matters | Takes effect | On this VM |
|---|---|---|---|
| `/etc/fstab` | A line without nofail whose device is missing becomes a hard requirement of local-fs.target: boot waits 90 s, then OnFailure=emergency.target drops to the emergency shell (generator test: dead UUID -> local-fs.target.requires). The root device comes from root=UUID on the kernel command line; the / line only supplies remount options and fsck pass. Note: The initrd carries a 0-byte fstab, so update-initramfs is not needed. Also watch /etc/fstab.d/*.fstab if it appears (the initramfs fsck hook reads it). | next boot; also at any systemctl daemon-reload (the fstab generator re-runs, and apt triggers reloads) or mount -a | exists, regular 0644 root:root 446 B, one by-uuid line, not package-owned; last changed 2026-09-27 08:26 (film demo sed -i then sc restore) |
| `/etc/crypttab` | On encrypted installs a wrong entry blocks unlocking root at boot (not verified here). Creating it must be seen. Note: Needs a non-recursive watch on /etc filtered to this name. | next boot or daemon-reload; on LUKS systems also update-initramfs (not verified) | missing; cryptsetup not installed |
| `/etc/default/grub` | Bad GRUB_CMDLINE_LINUX(_DEFAULT) root=/init= or a wrong GRUB_DEFAULT passes grub-script-check and breaks the next boot. Shell syntax errors abort grub-mkconfig, so the old grub.cfg stays. The menu is hidden, so the user cannot easily pick another entry. Note: A bad edit lies dormant until grub.cfg is regenerated. A grub-pc upgrade can rewrite it via ucf and debconf. | only after update-grub, which runs automatically on every kernel install or removal via /etc/kernel/postinst.d/zz-update-grub, including unattended security upgrades | exists, regular 0644 root:root 1550 B, ucf-managed by grub-pc (not a dpkg conffile), mtime 2025-10-30 |
| `/etc/default/grub.d/` | grub-mkconfig sources every *.cfg here after /etc/default/grub, so a drop-in silently overrides the main file. Note: Only *.cfg is active; a rename to *.cfg is itself an activation. | after update-grub (manual or at kernel install) | exists, empty dir 0755 root:root |
| `/etc/grub.d/` | Generator scripts for grub.cfg. Note: The exec bit is content (see special handling). | after update-grub (manual or at kernel install) | exists: 12 scripts 0755 root:root (00_header .. 41_custom, grub-common) plus README 0644 |
| `/boot/grub/custom.cfg` | 41_custom sources it at BOOT time, so creating or editing it changes the next boot with no update-grub. Note: Needs a non-recursive watch on /boot/grub that acts only on custom.cfg (plus grub.cfg as the applied marker). | next boot | missing |
| `/etc/initramfs-tools/` | Shapes the initrd. MODULES=dep or list on the wrong hardware can drop the disk driver, so boot stops at the (initramfs) shell. | `/etc/modprobe.d/` | Read by every modprobe. A blacklist or 'install X /bin/false' for ahci, ext4 or e1000 (this VM's only NIC, a loadable module) removes root or the network. Only *.conf is read. Note: Initramfs-fed source. | immediately for the next module load; next boot; early boot only after update-initramfs (all *.conf are copied into the initrd) | exists: 11 files 0644 (154-2507 B) plus blacklist-oss.conf -> /lib/linux-sound-base/noOSS.modprobe.conf (symlink) |
| `/etc/modules` | Modules loaded at boot, also reached through /etc/modules-load.d/modules.conf -> ../modules. A bad name makes systemd-modules-load fail, and boot continues (general systemd behaviour, not verified). Note: Snapshot the real file here; record the modules-load.d link as a link. | next boot or systemctl restart systemd-modules-load | exists, 0644 212 B, comments only, not package-owned |
| `/etc/modules-load.d/` | *.conf lists modules loaded at boot. A same-name file overrides /usr/lib/modules-load.d. | next boot or systemctl restart systemd-modules-load | exists: cups-filters.conf 119 B plus modules.conf -> ../modules (symlink) |
| `/etc/sysctl.conf` | Applied last at boot through /etc/sysctl.d/99-sysctl.conf -> ../sysctl.conf. Valid but harmful values (kernel.modules_disabled=1, vm.overcommit_memory=2 with a low ratio, a tiny pid_max) make the system unusable. Unknown keys are only logged. | next boot (systemd-sysctl), or immediately with sysctl --system or sysctl -p | exists, 0644 2209 B, no active lines, dpkg conffile |
| `/etc/sysctl.d/` | Same effects as sysctl.conf; only *.conf is read. | `/etc/systemd/system/` | Local units, drop-ins, enable links (*.wants/*.requires), masks (-> /dev/null), default.target and aliases. | `/etc/systemd/system.{control,attached}/` | Both are in the unit search path, and system.control has higher precedence than /etc/systemd/system. systemctl set-property writes persistent drop-ins into system.control (general systemd knowledge, not verified). Note: Needs a non-recursive watch on /etc/systemd for their creation; recurse once they appear. | daemon-reload or next boot | both missing (systemd-analyze unit-paths lists them) |
| `/etc/systemd/system-generators/` | Executables here run as root at every boot and every daemon-reload, before units load. A link to /dev/null masks the same-named /usr/lib generator. Note: Link records only. | next boot or daemon-reload | exists: systemd-gpt-auto-generator -> /dev/null (symlink, the only mask in /etc) |
| `/etc/systemd/system.conf` | PID 1 defaults for every service (DefaultTimeoutStartSec, DefaultLimitNOFILE, DefaultTasksMax, CPUAffinity, DefaultEnvironment). Also covers /etc/systemd/system.conf.d/*.conf. | next boot; daemon-reexec (not verified) | exists, 0644 2318 B, [Manager] header only, conffile; system.conf.d missing |
| `/etc/udev/rules.d/` | A same-name file REPLACES the /usr/lib rule. For 10 core names (50-udev-default, 60-block, 60-persistent-storage, 80-drivers, 80-net-setup-link, ...) the initramfs udev hook copies the /etc version into the initrd. So an empty 60-persistent-storage.rules removes /dev/disk/by-uuid, which both root=UUID and fstab need. NAME= rules rename NICs, so netplan's enp0s3 no longer matches. Note: 70-snap.* is excluded. The initrd copy of 70-snap.firefox.rules is already stale vs /etc (proof that initrd copies freeze). | next boot, or udevadm control --reload plus udevadm trigger; the initrd copy only after update-initramfs | exists: 5 files, all snapd-generated 70-snap.*.rules (2226-63357 B); no admin rules |
| `/etc/udev/udev.conf` | udevd settings (log level, event timeout), copied into the initrd. Low risk. | next boot; initrd copy after update-initramfs | exists, 0644 305 B |
| `/etc/tmpfiles.d/` | Processed at every boot: an 'R' or 'D' line deletes data. A same-name file masks /usr/lib/tmpfiles.d (for example the one creating /run/sshd). General systemd behaviour, not exercised here. Note: A naive '/etc/tmp*' exclude would hide this directory. | every boot, systemd-tmpfiles --create, and the daily clean timer | exists, empty dir |
| `/etc/ld.so.conf` | Input to ldconfig. Losing the include line, or adding a dir of incompatible libraries, changes the libraries every dynamically linked program loads. Note: Applied marker: /etc/ld.so.cache MOVED_TO. | after ldconfig, which the libc-bin dpkg trigger runs after most apt installs (17 times in dpkg.log, twice today) | exists, 0644 34 B 'include /etc/ld.so.conf.d/*.conf', conffile; also copied into the initrd |
| `/etc/ld.so.conf.d/` | Same as ld.so.conf; only *.conf is included; packages add files here. | after the next ldconfig (any package install) | exists: fakeroot-x86_64-linux-gnu.conf 38 B (added 2026-09-27 00:00), libc.conf 44 B, x86_64-linux-gnu.conf 100 B |
| `/etc/ld.so.preload` | The loader reads it for EVERY new dynamically linked process: no apply step, no reboot. A bad library breaks sudo, login, bash and every service start. Only static binaries survive (bin/sc, busybox). Note: Highest severity: alert on creation (non-recursive /etc watch). scd must stay static. | immediately | missing |
| `/etc/kernel/` | postinst.d, postrm.d and preinst.d run via run-parts --exit-on-error on every kernel install. zz-update-grub and initramfs-tools there make a new kernel bootable. chmod -x, a rename to *.sh, or a delete silently stops initrd or grub.cfg generation for the next kernel. A non-zero exit leaves the kernel half-configured. Note: Mode and name are content. | next kernel install or removal (unattended security upgrades) | exists: postinst.d = initramfs-tools, unattended-upgrades, update-notifier (symlink -> /usr/share/...), xx-update-initrd-links, zz-update-grub (all 0755); postrm.d 2; preinst.d 1; install.d empty; /etc/kernel/cmdline absent |
| `/etc/apparmor.d/{tunables,abstractions,abi}/` | Shared includes: tunables/global alone is included by 112 profiles. One syntax error makes every profile fail to parse at the next apparmor.service run. Confinement is lost and snap-confine's profile fails, so snaps such as Firefox likely stop launching (snap effect not verified). Boot itself continues. Note: Borderline tier 1 (reaching a usable state, not booting). The rest of /etc/apparmor.d is tier 4. | next boot (apparmor.service, Before=sysinit.target) or systemctl reload apparmor | exists: tunables/global 897 B, abstractions/base 7093 B; aa-status: 157 profiles loaded |

### Tier 2: access

A mistake locks people out: sudo, console login, ssh, desktop login. Most bite immediately (next sudo, next login). The ssh and GDM files bite only at the next service start, which is a delayed bomb.

| Path | Why it matters | Takes effect | On this VM |
|---|---|---|---|
| `/etc/sudoers` | sudo re-reads it on every run. If it is not owned by uid 0 or is world-writable, sudo refuses for everyone (verified in a private mount namespace). An empty file, or one missing '@includedir /etc/sudoers.d', drops every rule. A bad line is skipped by sudo 1.9.15. Note: visudo -c -f passed a 0666 copy, so owner and mode must be checked separately. Restore exactly 0440 root:root. | immediately (next sudo) | exists, 0440 root:root 1800 B, sudo conffile, unmodified |
| `/etc/sudoers.d/` | Every name without '.' and without a trailing '~' is live policy the moment it appears, including README. A broken drop-in is skipped, which loses what it granted: here vboxuser loses NOPASSWD and sudo -n fails. Note: The NOPASSWD rule hides most sudoers breakage on this VM; test with a user that has no NOPASSWD rule. | immediately | exists: README 0440 1068 B (parsed), 90-vboxuser-nopasswd 0440 33 B 'vboxuser ALL=(ALL) NOPASSWD: ALL' (created 2026-09-27 00:48, unowned) |
| `/etc/sudo.conf` | Read on every sudo run. A Plugin line pointing at a missing .so blocks sudo completely. Junk lines or an empty file are tolerated. A non-root owner makes sudo ignore the file. | immediately | exists, 0644 4343 B, all comments, conffile |
| `/etc/pam.d/` | A missing required module in common-account blocks sudo, su, ssh, console and GDM for everyone (verified: even root's su failed). ### Tier 3: network and updates

A mistake cuts the machine off or breaks apt. Several of these are not package-owned, so apt --reinstall cannot restore them, and a broken apt config blocks the apt command that would fix it.

| Path | Why it matters | Takes effect | On this VM |
|---|---|---|---|

## 3. Special handling

**`/etc/{passwd,group,shadow,gshadow,subuid,subgid} (account set)`**  
Problem: useradd/usermod rewrite several files in one locked transaction (FILE.<pid> -> FILE.lock, FILE- backup, FILE+ -> rename), so a snapshot taken mid-way is inconsistent. A single-file restore desyncs the set: the older passwd- lacks the sshd user and 'sshd -t' then fails; the older group- drops vboxuser from sudo; an older shadow reverts the 2026-09-26 password and the GNOME keyring. shadow and gshadow hold hashes. pam_unix password changes (nshadow -> rename) touch only shadow.  
Handling: Debounce the set until no /etc/<member>.lock exists, then snapshot all changed members as one change group. Redact field 2 of shadow and gshadow in diff, log and journal output ('password hash changed for USER'). Keep modes and owners exactly: shadow and gshadow 0640 root:shadow (0600 root:root broke unix_chkpwd, so the lock screen cannot unlock). A later restore works on the set only, validated with pwck -r and grpck -r, holding the shadow-utils locks, with a per-user summary.

**`/etc/pam.d/common-{auth,account,password,session,session-noninteractive} with /var/lib/pam/`**  
Problem: Generated by pam-auth-update (all five rewritten within 16 ms at 2026-09-23 17:04:22 during apt), which keeps its state in /var/lib/pam/*. Restoring common-* without matching state makes the next pam-auth-update treat the difference as local edits.  
Handling: Group the five files as one change. Ignore *.pam-new/*.pam-old. Record /var/lib/pam/* hashes as read-only metadata, never restore them automatically, and warn when they disagree.

**`/boot/grub/grub.cfg`**  
Problem: This is the file GRUB actually reads (0600 root, 10431 B). It is generated from /etc/default/grub, /etc/default/grub.d and /etc/grub.d, and rewritten IN PLACE ('cat grub.cfg.new > grub.cfg'), so the first MODIFY is a truncation to 0 bytes. Hand edits are overwritten at the next update-grub, and an old copy may reference kernels removed since.  
Handling: Act only after CLOSE_WRITE plus the quiet period. Record (hash, mtime) as the 'bootloader applied' marker for its sources. Whether to also keep content as a last-good rescue copy is open question 6. The normal fix is to restore the sources and run update-grub.

**`/boot/initrd.img-*, /boot/vmlinuz-*, /etc/ld.so.cache`**  
Problem: Generated outputs. The initrds are 80-82 MB (over the 8 MB cap) and are written as .new then 'mv -f' (MOVED_TO in /boot). ld.so.cache is written as ld.so.cache~ then renamed by ldconfig after most apt installs (08:02:49 and 19:15:41 today).  
Handling: Never snapshot their content. Watch /boot and /etc non-recursively for MOVED_TO of these names and record (name, size, mtime, sha256) as 'initramfs applied' and 'ld.so.conf applied' markers. Recovery is to rerun update-initramfs -u or ldconfig.

**`Initramfs-fed sources: /etc/initramfs-tools/**, /etc/modprobe.d/*.conf, /etc/udev/rules.d/*.rules, /etc/udev/udev.conf, /etc/systemd/network/*.link, /etc/default/{keyboard,console-setup}, /etc/ld.so.conf(.d), /etc/nsswitch.conf`**  
Problem: The initrd holds frozen copies taken at update-initramfs time. Restoring the /etc file does not fix early boot, and the initrd can still hold a bad version after /etc is fixed (the initrd's 70-snap.firefox.rules already differs from live).  
Handling: Tag snapshots of these paths as 'initramfs source'. Restore output must say 'also run: update-initramfs -u'. Later, compare snapshot time with the initrd mtime to say which version early boot uses.

**`Symlinks: /etc/systemd/system/**/*.{wants,requires}/*, masks to /dev/null, /etc/systemd/system/{default.target,display-manager.service}, /etc/systemd/system-generators/*, /etc/localtime, /etc/default/locale, /etc/vconsole.conf, /etc/modules-load.d/modules.conf, /etc/sysctl.d/99-sysctl.conf, /etc/modprobe.d/blacklist-oss.conf, /etc/pam.d/gdm-smartcard, /etc/profile.d/debuginfod.{sh,csh}, /etc/lighttpd/conf-enabled/*, /etc/xdg/systemd/user`**  
Problem: Enable, disable, mask, default target and timezone are pure symlink state, and creating a link emits only IN_CREATE. sc refuses symlinks today; /etc has 791 of them. /etc/xdg/systemd/user is a directory symlink that would double-watch /etc/systemd/user.  
Handling: lstat and never follow. Record a link record (target string, lstat owner); flag a link to /dev/null as 'masked'. For links whose target is inside /etc, also watch the real file. Restore is symlink-to-temp plus rename. Never add a watch through /etc/xdg/systemd/user. Whether this is M2 is open question 3.

**`/etc/resolv.conf`**  
Problem: On this VM it is a regular file (installer copy of the stub); on stock 24.04 it is a symlink into /run/systemd/resolve whose content churns on every DHCP event. Writes through the symlink are invisible to an /etc watch, and sed -i turns the symlink into a regular file.  
Handling: Record the type. As a symlink, record only the target and never follow it into /run; as a regular file, snapshot the content. Treat a file-to-symlink flip (or the reverse) as a notable event. Restoring the stock symlink is a type change M1's restore cannot express.

**`/etc/ssh/ssh_host_{rsa,ecdsa,ed25519}_key (with .pub)`**  
Problem: Private host keys (0600 root, 399-2590 B). At mode 0644 sshd ignores a key, and with no usable key it exits 'no hostkeys available'. Restoring an old key after a rotation flips the fingerprint every client sees and can resurrect a compromised key.  
Handling: Always record hash, mode and owner, and alert on any ATTRIB mode change. Whether to store content (0600 blobs) is open question 5. Snapshot and restore each private key together with its .pub; never auto-restore.

**`Secret-bearing watched files: /etc/shadow, /etc/gshadow, /etc/netplan/*.yaml, /etc/NetworkManager/system-connections/*, /etc/apt/auth.conf.d/*, /etc/sssd/sssd.conf`**  
Problem: Snapshots copy secrets (hashes, PSKs, repo credentials), and sc diff, sc cat and log output print content on the console.  
Handling: Store blobs 0600 in a 0700 store (already true). Mark files secret by path list, with 'not world-readable' as a hint. Redact hash, psk=, password= and private-key values in diff, log and scd journal messages. Restore the exact mode and owner (NM ignores keyfiles that are not 0600 root).

**`Existence flags: /etc/ld.so.preload, /etc/nologin, /etc/ssh/sshd_not_to_be_run`**  
Problem: Their mere existence changes behaviour: ld.so.preload affects every new process; nologin makes pam_nologin block every non-root login (login, sshd, gdm-*); sshd_not_to_be_run stops ssh.socket and ssh.service at their next start. All are absent today. 'Restore' means delete, which sc cannot express. /run/nologin is created by systemd at shutdown, so ignore that one.  
Handling: Non-recursive watches on /etc and /etc/ssh filtered to these names, firing on CREATE and MOVED_TO. Record a 'did not exist' baseline and raise an alert, ld.so.preload at the highest severity. Snapshot ld.so.preload content; the other two are flags only.

**`Mode-is-content: /etc/grub.d/*, /etc/kernel/{postinst,postrm,preinst}.d/*, /etc/initramfs-tools/{hooks,scripts}/**, /etc/gdm3/*/Default`**  
Problem: The exec bit decides whether grub-mkconfig or run-parts runs a script at all. chmod -x 10_linux gives no Linux entries at the next update-grub. Renaming zz-update-grub to zz-update-grub.sh makes run-parts skip it. Both emit only ATTRIB or a rename, with no content change.  
Handling: IN_ATTRIB triggers a metadata comparison and a metadata-only row. Raise a specific alert when an exec bit disappears, or when a hook is renamed to a name run-parts skips (a dot, or a character outside [A-Za-z0-9_-]).

**`Vendor overrides: /etc/udev/rules.d/*.rules, /etc/sysctl.d/*.conf, /etc/tmpfiles.d/*.conf, /etc/modules-load.d/*.conf, /etc/NetworkManager/conf.d/*.conf, /etc/netplan/*.yaml`**  
Problem: An /etc file with the same basename as the /usr/lib one replaces it, and an empty file or a /dev/null link disables it. For udev, the initramfs hook also prefers /etc/udev/rules.d/60-persistent-storage.rules.  
Handling: On CREATE, check /usr/lib/<dir>/<name> (also the /lib form, because dpkg records /lib paths under usrmerge) and label the event 'overrides vendor file' with raised severity. Keep a critical-name list: 50-udev-default, 60-block, 60-persistent-storage, 80-drivers, 80-net-setup-link, 10-apparmor, 99-protect-links, 10-globally-managed-devices.

**`/etc/apt/sources.list.d/google-chrome.sources, /etc/default/google-chrome`**  
Problem: /etc/cron.daily/google-chrome (a symlink to /opt) rewrites both every day with identical content (tmp + mv, sed -i), which would produce one snapshot per day forever.  
Handling: Content-plus-metadata dedup yields no new row. Optionally tag rows from this job as origin=cron.

**`ucf- and dpkg-managed files: /etc/default/grub, /etc/ssh/sshd_config, /etc/apt/apt.conf.d/{20auto-upgrades,50unattended-upgrades}, and the 1486 dpkg conffiles`**  
Problem: Package upgrades legitimately rewrite them. Restoring an older version makes dpkg or ucf see the file as locally modified, so the next upgrade prompts, keeps the stale copy or merges oddly.  
Handling: Record the owning package and the dpkg/ucf md5 in snapshot metadata. Attribute apt-time changes to apt. After a restore, warn when the file no longer matches the package version.

**`/root/.ssh/, /home/*/.ssh/`**  
Problem: Outside /etc. Files are user-owned in 0750 homes, sshd StrictModes rejects group- or world-writable files, and the set of homes changes with /etc/passwd.  
Handling: Derive homes from /etc/passwd login shells, not a /home glob. Add or remove watches when passwd changes. Restore must chown back to the user and keep 0600.

## 4. Design rules for scd

1. **Watch directories, never individual files. Filter by name in user space and key records by path.**  
   Because: inotify watches inodes. Every rename-over writer (sed -i, mv, dpkg, visudo, useradd, sc restore) kills a file watch, and later edits are lost. vim's rename-style save moves the watch to FILE~.

2. **Use the mask IN_CLOSE_WRITE|IN_MOVED_TO|IN_MOVED_FROM|IN_CREATE|IN_DELETE|IN_ATTRIB|IN_DELETE_SELF|IN_MOVE_SELF with IN_DONT_FOLLOW|IN_ONLYDIR. Treat every one of them as 'path is dirty'. Use IN_MODIFY only to extend the debounce. Never subscribe to OPEN, ACCESS or CLOSE_NOWRITE.**  
   Because: No single event means 'final'. In-place writers end with CLOSE_WRITE; rename writers end with MOVED_TO, and a mv from outside the dir gives only MOVED_TO. install and vim set the mode by ATTRIB after close. gio and visudo emit CLOSE_WRITE after MOVED_TO. chmod and chown give only ATTRIB, and a new symlink gives only CREATE. Read events would make scd trigger itself.

3. **Keep a per-path quiet period (start at about 500 ms, cap at a few seconds). Then lstat, read and hash, fstat again, and accept only if size, mtime, ctime and inode are unchanged; otherwise retry, and at the cap record the row marked 'unstable'. Never snapshot on MODIFY.**  
   Because: nano, cp, tee, '>', sudoedit write-back, ucf (cp -f) and grub-mkconfig all truncate first and write in place, so a MODIFY-time read sees 0 bytes or partial content.

4. **Apply a structural temp-file rule: when a path's quiet period ends, snapshot it only if it still exists, is a regular file or symlink, and passes include/exclude; drop everything else. Exclude globs are a noise filter, not the correctness mechanism.**  
   Because: Temp names are unpredictable (ln -sf 'Cu0SWPQ0', patch 'a.conf.oEjj3Ws', rsync '.a.conf.O4dxr3') and most get CLOSE_WRITE before being renamed away. Some live files look temporary (apt.conf.d/zzzz-temp-installer-unattended-upgrade).

5. **Treat DELETE or MOVED_FROM of a tracked name as a deletion only if the path is still absent when the quiet period ends. Then write a deletion row that points at the last blob.**  
   Because: vim, cp -b, install, rm plus recreate, and git checkout all remove the name before the new file appears. Real deletions are real config changes, such as a deleted drop-in or conffile.

6. **Deduplicate every origin on (sha256, mode, uid, gid, file type, link target) against the latest row. An mtime-only change is not a change.**  
   Because: touch, no-op chown, ed, gio, dpkg's fsync pass, shadow-utils opening group read-write, grub-editenv and chrome's daily cron all emit write events without changing anything. The current store dedups only OriginManual, and only on the blob, so auto rows would flood and mode-only changes would be missed.

7. **Make metadata-only changes first-class: on ATTRIB, compare mode, uid and gid, and record a metadata-only row that points at the same blob.**  
   Because: Several lockouts and boot failures are ATTRIB-only: chmod -x /etc/grub.d/10_linux leaves no Linux entries at the next update-grub; /etc/sudoers at 0666 makes sudo refuse; /etc/shadow at 0600 root:root breaks unix_chkpwd; a host key at 0644 is ignored.

8. **On CREATE|ISDIR or MOVED_TO|ISDIR, add the watch first, then readdir recursively and mark every entry dirty.**  
   Because: Files written into a new directory before its watch exists can produce no event. dpkg creates directories as NAME.dpkg-new and renames them. A populated directory moved in reports only itself. systemctl edit creates <unit>.d/ and then override.conf immediately.

9. **Keep a live wd-to-path map. Rewrite prefixes on MOVED_FROM/MOVED_TO|ISDIR cookie pairs, drop watches on an unpaired MOVED_FROM|ISDIR and on IN_IGNORED, and rescan the subtree when unsure.**  
   Because: After a directory rename its wd keeps reporting bare names, so a map built when the watch was added produces wrong absolute paths.

10. **Drain the inotify fd in a dedicated goroutine into an in-memory dirty set, so SQLite fsyncs never block reading. On IN_Q_OVERFLOW, run a full rescan of every watch root against the latest rows.**  
   Because: The queue holds 16384 events per inotify instance (root is not exempt). When it fills, the kernel keeps the queued events, drops one continuous stretch of new ones, and adds a single IN_Q_OVERFLOW marker (wd=-1) that does not say which paths were affected, including other, quiet watches. Events carry no content, so the final state is still on disk: a rescan comparing disk with the last snapshot recovers it. Intermediate versions written during the lost stretch cannot be recovered. (Verified on this VM.)

11. **Run a full rescan at every scd start (baseline-snapshot every included file; dedup keeps repeats cheap) and a daily backstop. Compare hash plus inode and ctime, never mtime alone. Stamp rows with wall-clock time and /proc/sys/kernel/random/boot_id, never uptime.**  
   Because: Nothing reports changes made while scd was down, at boot or pre-OS (grubenv, netplan generator), from the rescue shell, through hard links, or behind symlinks. inotify reports after the fact, so the 'before' version must already be stored. cp -p and rsync -t reset mtime. uptime lies on a paused VM.

12. **Make restores announce themselves. sc restore commits an intent marker (path, blob, pid, expiry) or its row before the rename, or scd treats a change whose hash equals a recent restore row for that path as origin=restore. Ignore .*.sc-tmp-* names. Test this with an in-process watcher.**  
   Because: store.Restore renames the file (store.go:341) before it commits its 'restore' row (store.go:349). Measured gap on this VM: 9.9-61.7 ms, median 19.5 ms, over 30 runs. A watcher that acts on MOVED_TO right away recorded an extra unattributed row in 20 of 20 trials. A settle delay only makes it unlikely (1/20 at 25 ms across processes). The deterministic fixes: restore records its intent (or row) before the rename, or restore holds the SQLite write lock across rename and insert while scd checks and inserts in one IMMEDIATE transaction.

13. **Refuse to start if $SC_HOME, scd's log file or its temp dir lies under any watch root. Never write per-event lines under /etc.**  
   Because: Writing inside a watched tree feeds back on itself.

14. **Use one inotify instance with directory watches only, and never recurse into /usr, /var or /run. On ENOSPC from inotify_add_watch, log it loudly, move that subtree to periodic rescans, and show it in sc status.**  
   Because: max_user_watches (65536) and max_user_instances (128) are per uid and shared with every root process. 65536 comes from a desktop package, so a server install may differ. /etc needs about 330-400 watches.

15. **Never follow symlinks: walk with lstat semantics (filepath.WalkDir), add watches with IN_DONT_FOLLOW|IN_ONLYDIR, and record symlinks as link records.**  
   Because: /etc has 791 symlinks, and systemd enable/mask, localtime and alternatives are link state. /etc/xdg/systemd/user is a directory symlink. Links point into /proc, /run, /opt and /dev/null.

16. **Group package operations. Guarded apt hooks (DPkg::Pre-Invoke / DPkg::Post-Invoke, 'if [ -x ... ]; then ...; fi' plus '|| true') can bracket a change set with origin=apt and snapshot pending human edits at the start. Fall back to a time window while /var/lib/dpkg/lock(-frontend) is held, with a stale-marker timeout.**  
   Because: One apt upgrade touches about 110 /etc entries in 10 minutes. Bare dpkg -i, dpkg triggers (libc-bin ldconfig), snapd refreshes and cron jobs bypass the apt hooks. A failing hook aborts apt.

17. **Label every name active or inert for its directory's consumer. Record everything in scope, alert only on active names, and report activations and deactivations caused by renames.**  
   Because: sudoers.d parses names without '.' or a trailing '~' (so README is parsed). apt reads extensionless and .conf files. netplan reads non-hidden *.yaml. modprobe.d, sysctl.d, modules-load.d, tmpfiles.d and ld.so.conf.d read only *.conf; udev reads *.rules; default/grub.d reads *.cfg; run-parts requires [A-Za-z0-9_-]. A rename can be the whole edit.

18. **Keep sc's temp name dot-prefixed and containing a dot ('.<base>.sc-tmp-*'). Never create an extensionless, *.conf or *.yaml temp name inside /etc.**  
   Because: That name is ignored by sudoers.d, apt.conf.d, sources.list.d, preferences.d, netplan and every *.conf reader. An extensionless temp in apt.conf.d breaks every apt command while it exists. Exception found by verification: logrotate reads hidden files in /etc/logrotate.d (its tabooext does not cover .sc-tmp-*), so a restore there briefly exposes a duplicate stanza. grub-mkconfig is safe because its '*' glob skips dotfiles. Consider a temp suffix that logrotate's tabooext skips.

19. **scd is static (CGO_ENABLED=0), runs as root, does not shell out on its hot path, and does no NSS lookups (numeric uid/gid only).**  
   Because: /etc/ld.so.preload or a bad ld.so.cache breaks every dynamically linked binary immediately. A broken nsswitch.conf makes users vanish. 34 /etc files are not world-readable.

20. **Define scd's glob language explicitly: '*' is one segment, '**' is any depth, braces are expanded by scd, char classes are allowed. Ship a test that runs every default exclude against a real /etc listing and asserts that no tier-1 or tier-2 path is excluded. Treat paths as opaque bytes, escape \ * ? [ when turning a literal path into a pattern, and print paths with %q.**  
   Because: find's -path '*' crosses '/', while Go's filepath.Match does not and has no '**' or braces. '/etc/tmp*' would hide /etc/tmpfiles.d. 30 snap unit paths contain literal backslashes, and one cert name is UTF-8.

21. **Track 'edited' vs 'applied'. Record generated outputs as markers (grub.cfg CLOSE_WRITE, /boot/initrd.img-* MOVED_TO, /etc/ld.so.cache MOVED_TO). A source newer than its output is 'pending until <command>'.**  
   Because: Most boot files take effect only after update-grub, update-initramfs, ldconfig or daemon-reload. Unattended upgrades run these with nobody present, so 'the machine still works after my edit' proves nothing.

22. **Do not promise 'who changed it' in M2. Attribute only to sc (its own marker), apt (the dpkg lock and log window) and known generators by name.**  
   Because: struct inotify_event carries only wd, mask, cookie, len and name. fanotify gives a pid, but short-lived writers such as sed -i are gone by the time it is read. auditd is not installed.

23. **When validators arrive (M3), run only check-only forms on scratch copies, and never synchronously inside the event loop.**  
   Because: Some commands that look like checks apply changes. Safe check-only forms exist for most consumers.

### Watched but should not be (as proposed)

### Missing design rules

- **Metadata must include inode flags (FS_IOC_GETFLAGS: immutable, append-only) and ACL/xattrs (system.posix_acl_access). On every IN_ATTRIB compare those too, not just mode, uid and gid. Before a restore, check for +i/+a and fail with one clear line naming the flag.**  
  Because: chattr +i and setfacl emit only IN_ATTRIB and leave the mode unchanged, so the plan's (mode, uid, gid) comparison and dedup key record nothing. After chattr +i the rename-over restore and dpkg upgrades of that file fail, even as root. An ACL entry can grant a user write access to a sudoers drop-in or read access to shadow with 'ls -l' mode bits unchanged.
- **Directory metadata is content: record mode, owner, flags and ACL of every watched directory, and of each home dir and .ssh dir on the SSH path. Handle ATTRIB|ISDIR from both the parent watch and the self event.**  
  Because: sudo drops the entire sudoers.d when that directory is world-writable, which silently removes vboxuser's NOPASSWD rule. sshd StrictModes checks the home directory too, so 'chmod g+w /home/vboxuser' disables key login. The plan's metadata rows are per file only, and it watches .ssh, not the home dir.
- **Give the store a disk budget. Keep a free-space floor (stop auto snapshots before touching root-reserved blocks), set a per-path rate limit and a retention policy for auto rows, and raise one alert when a limit is hit. On ENOSPC, EDQUOT, EROFS or SQLITE_FULL, enter a degraded mode: keep a bounded in-memory dirty set, retry with backoff, never crash-loop, never delete blobs to make room, and mark the gap for the next rescan.**  
  Because: $SC_HOME shares one ext4 filesystem with /, /etc and /home. scd runs as root, so it can eat the reserved blocks that exist so root can recover a full disk. Some watched files are user-writable (authorized_keys, crontabs), so an unprivileged user can make root write up to 8 MB per distinct version, as fast as they like. M1 has no pruning. A read-only root (rescue, emergency, remount-ro) makes every store write fail.
- **Treat paths under user-owned directories as hostile. Open with O_NOFOLLOW|O_NONBLOCK (or openat2 RESOLVE_NO_SYMLINKS for every component), compare dev and inode of the lstat with the fstat, reject non-regular files after open, use only non-recursive watches there, and do restores with openat on a directory fd checked the same way (or drop to the owner's uid).**  
  Because: ReadWithMeta lstats the path, then os.Open follows symlinks, and plain open blocks on a FIFO. A user who swaps ~/.ssh/authorized_keys (or ~/.ssh itself) for a symlink between the two calls gets root to read /etc/shadow or /root/.ssh into the store. A FIFO hangs the scd worker. WriteAtomic resolves the directory by path, so a symlinked ~/.ssh redirects a root restore. A recursive watch in a user dir lets a user burn root's shared watch budget (max_user_watches 65536, shared with dbus-daemon, polkitd and PID 1).
- **Build an active/inert consumer table per directory and apply it BEFORE the global noise excludes. In directories whose consumer runs or loads names by a glob or character class (/etc/grub.d, /etc/initramfs-tools/hooks and scripts/*, /etc/apparmor.d), the backup and temp suffix excludes must not apply. Extend the planned exclude test to synthetic names (X.bak, X.old, X.disabled, X.tmp, X.dpkg-old in each consumer dir), not just today's /etc listing.**  
  Because: Today's listing has none of these names, so the plan's test ('run every default exclude against a real /etc listing') passes while excluded names are executed or loaded.
- **Order rows by a monotonic insert sequence (rowid), never by wall-clock ts, for 'latest', dedup and default restore choice. Keep ts and boot_id as labels only.**  
  Because: Wall-clock time can step backwards: RTC time before NTP sync, a VM snapshot restore, manual date. A row inserted after a backward step then sorts below older rows. Dedup then compares against the wrong row (spurious or missed auto rows), and 'latest' points at the wrong version during an incident. The plan's boot_id stamping does not fix ordering.
- **Design scd's unit so it can never block or blind boot. No ProtectHome=, ProtectSystem=strict or TemporaryFileSystem= over watch roots; no unit that logins or network need is ordered After=scd; start timeout short, and READY sent before the baseline scan; add all watches BEFORE the baseline scan, both at start and after an overflow.**  
  Because: ProtectHome makes /home and /root empty inside the service, so the SSH watches would silently watch nothing (or a tmpfs). rc-local.service shows how one late unit with no timeout blocks gdm and every getty. Scanning before watching loses edits made in between.
- **Keep scd's SQLite write transactions short: commit the baseline and rescans in small batches, and never hold a write transaction across hashing or fsync of watched files. Weigh WAL against M4's read-only-root reads before switching journal mode.**  
  Because: The sc CLI waits only 5 s for the lock, then fails. An admin running 'sc restore' during an incident while scd writes a 1144-file baseline in one transaction (or fsync-heavy rows during apt) gets 'database is locked'. A WAL database cannot be opened on a read-only root unless its -shm/-wal files already exist (SQLite documentation, not verified here).
- **Track mounts. Read /proc/self/mountinfo at start and re-read it on POLLPRI. When a filesystem is mounted over a watched directory, or unmounted from under it (IN_UNMOUNT), re-add the watches and rescan. For filesystems without POSIX ownership (vfat ESP), record content only and skip chown/chmod on restore.**  
  Because: A watch sits on the inode that was visible when it was added. Mounting /boot or /boot/efi later hides that directory, and the watch reports nothing from the new mount. Not an issue on this VM (single ext4 root, BIOS), but it is on typical UEFI and separate-/boot installs.

## 6. Verification of key claims

Each claim was re-tested on this VM by an agent told to refute it.

| On IN_Q_OVERFLOW the kernel keeps the oldest 16384 events and silently drops the newer ones, which are exactly the final states. scd must full-rescan on overflow. | **partly-true** | What holds on this VM: the queue limit is 16384 events per inotify instance. When the queue is full, the kernel keeps the oldest events and drops the new ones. It then adds exactly one IN_Q_OVERFLOW event (wd=-1, mask=0x4000, len=0) after the 16384 kept events. Root is not exempt. The limit counts events, not bytes. scd does need to rescan on overflow, and the rescan must cover every watched path, because the marker has wd=-1 and events for a different, quiet watch are lost too (twowd test).  What is wrong or needs precision: (a) The drop is not silent. The kernel sends one IN_Q_OVERFLOW event. What it does not say is which events, watches or paths were lost. (b) "Keeps the oldest 16384" is only true while the queue stays full. Those are the final states only if the burst ends while the reader is still stalled, as in this probe. (c) Events are lost, not states. inotify events carry no file content, so the final content is still on disk. That is why a rescan can recover it: compare what is on disk now with the last snapshot. A file with an event before the cutoff gets its final content read when scd handles that event (alt test). The real gap is files with no surviving event at all. ## 7. Changes needed in M1 code before M2

Found during this research and confirmed by reading the code. None of them affects M1 as used today (root runs `sc` by hand on root-owned files), but each must be fixed before a daemon runs `sc`'s code automatically.

1. **Fixed in `c720f22`. Read race in `fsutil.ReadWithMeta`.** It calls `os.Lstat(path)`, then `os.Open(path)` again by name, which follows symlinks, and does not compare device and inode. If the file is swapped for a symlink in between, root copies the link's target (for example `/etc/shadow`) into the store; a FIFO swapped in makes the read hang. Fix: open with `O_NOFOLLOW|O_NONBLOCK`, compare `lstat` and `fstat` dev/inode, reject non-regular files after open.
2. **Fixed in `ec15ece`. Restore writes before it records.** `store.Restore` renames the file (store.go:341) before inserting its row (store.go:349), a 10-60 ms window in which a watcher sees an unexplained change. Fix: record the intent before the rename, or hold the write lock across both (see rule 12).
3. **Tested, left as is. Temp name and logrotate.** Confirmed with `logrotate -d`: it reads `.<name>.sc-tmp-N`, and also names ending in `~`, `.dpkg-tmp` or `.swp`, so no suffix avoids it. Impact: one skipped duplicate stanza if logrotate runs during a restore's few milliseconds. `.<name>.sc-tmp-N` is ignored by apt, sudo, netplan, systemd and other `*.conf` readers, but logrotate reads hidden files in `/etc/logrotate.d`. Consider a suffix logrotate skips.
4. **Symlinks and metadata.** `sc` refuses symlinks, but `/etc` has 791 of them (systemd enable/mask links, `localtime`); `sc` also ignores immutable flags and ACLs, which the critic shows can lock people out. These are M2 scope decisions (section 8).

1. Scope: watch only the tier 1-3 paths listed here, or sweep all of /etc minus the exclude list (about 324 dirs, 1144 files, 2.46 MB) and use tiers only for alert priority?
2. Tier 4: watched by default, or opt-in per path?
3. Symlinks: add a link-record type in M2 (needed for systemd enable/mask, default.target and localtime), or leave symlinks unrecorded until later?
4. Deletions and creations: record 'deleted' and 'did not exist' rows in M2 (restore then means delete or recreate), or record content changes only?
5. SSH host private keys (and other secrets beyond shadow): store full content as 0600 blobs, or only hash plus mode and owner?
6. /boot/grub/grub.cfg: keep full copies as rescue material (origin=generated), or record only its hash as the 'applied' marker?
